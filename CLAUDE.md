# ArchTry — переезд на Arch + Hyprland (dual boot с Windows)

Репозиторий-штаб переезда Huawei Matebook X Pro 2020 (MACHC-WAE9LP) на Arch Linux + Hyprland
с сохранением Windows. Здесь документация, решения и (позже) скрипты автоустановки и dotfiles.

## Что читать в первую очередь

1. `docs/CONTEXT.md` — сводка всех прошлых обсуждений: железо, текущий диск, целевая разметка, порядок работ, риски.
2. `docs/DECISIONS.md` — принятые решения и **открытые вопросы**. Прежде чем что-то делать, проверь открытые вопросы.
3. `docs/INSTALL.md` — пошаговая установка: разметка → Windows → Arch → первая загрузка.
4. `docs/PROGRESS.md` — где мы сейчас. **Обновляй его после каждого завершённого шага.**

`legacy/` — апрельские наработки (rEFInd, ext4, archinstall 2.x). Устарели, не использовать как источник решений.

## Кратко о системе

- CPU i7-10510U, 16 ГБ RAM, Intel UHD 620 + NVIDIA MX250 (NVIDIA гасим: `envycontrol -s integrated`)
- WiFi/BT Intel AX201; fingerprint Goodix не работает; часть динамиков может молчать (sof-firmware)
- SSD TOSHIBA KXG60ZNV1T02 1 ТБ, `/dev/nvme0n1`, GPT, UEFI
- Экран 3000×2000 — в TTY нужен крупный шрифт (`setfont ter-132b`), в Hyprland scale 2
- Своп: zram + `/swap/swapfile` 20 ГиБ, закрытая крышка → сон → через 3 ч гибернация
- Загрузчик: **systemd-boot**, один общий ESP 1 ГиБ смонтирован в `/boot`
- Arch на BTRFS (zstd, noatime), Share — NTFS через драйвер ядра `ntfs3`, монтируется в `/mnt/share`

## Правила работы (обязательно)

- Перед деструктивными командами (`sgdisk`, `fdisk`, `mkfs.*`, `wipefs`, `rm -rf`, `dd`) — предупредить,
  объяснить, что именно будет уничтожено, и **ждать явного подтверждения**. Сначала показать `lsblk -f`.
- Давать полные команды и полные файлы с путями. Объяснять, что и зачем — пользователь учится.
- На установленном Arch перед рискованными изменениями — BTRFS-снапшот.
- Комментарии в конфигах: пользовательские — на русском, технические — на английском.
- Проблемы и их решения → `docs/TROUBLESHOOTING.md`; новые решения → `docs/DECISIONS.md`.
- Код — только на Arch в `~/projects` под git; на Share код не класть (см. правила раскладки в `docs/CONTEXT.md`, раздел 5).
- Visual Studio и аудио-стек (VST/ASIO) остаются на Windows — Windows должен оставаться рабочим.
