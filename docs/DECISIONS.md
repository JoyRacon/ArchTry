## Принятые

### D1. Разметка: весь диск заново, Windows ставится первой (сентябрь 2026)
Порядок: `ESP 1G | MSR + Windows 250G + Recovery (создаст установщик) | Arch 350G BTRFS | Share 250G NTFS | ~100G запас`.
- Windows ставится первой, потому что её установщик перезаписывает загрузочные записи.
- ESP создаём сами размером 1 ГиБ до установки Windows, иначе установщик сделает 100 МБ.
- Под Windows оставляем **неразмеченное** место: установщик сам создаст там MSR, C: и Recovery и возьмёт наш ESP.
- Отвергнуто: апрельская схема 300/400/280 с exFAT.

### D2. Загрузчик: systemd-boot
Нативный для UEFI, простой, сам находит Windows Boot Manager на том же ESP. ESP смонтирован в `/boot`, ядра лежат прямо на нём, поэтому ESP нужен 1 ГиБ.
Отвергнуто: rEFInd (апрельский скрипт в `legacy/`), GRUB.

### D3. Share на NTFS (драйвер `ntfs3`), не exFAT
NTFS журналируемая, Linux пишет в неё через ядерный `ntfs3`. Форматируем из Windows.
Условие: в Windows отключён Fast Startup, иначе том остаётся «грязным» и Linux монтирует его только на чтение.

### D4. GPU: только Intel
MX250 почти не даёт прироста против встроенной графики, зато мешает Wayland и жрёт батарею. `envycontrol -s integrated`. При необходимости — `-s hybrid` и PRIME offload.

### D5. BTRFS subvolumes (предложено, см. Q2)
```
@           → /
@home       → /home
@snapshots  → /.snapshots
@var_log    → /var/log
@var_cache  → /var/cache
@swap       → /swap        (только своп-файл, в снапшоты не попадает)
```
Почему не `@var` целиком: база pacman лежит в `/var/lib/pacman`. Если `/var` в отдельном subvolume, то откат `@` на снапшот
вернёт старые файлы системы, но оставит новую базу пакетов. После такого отката pacman считает, что стоят версии, которых на диске уже нет.
Рекомендация Arch Wiki для snapper — выносить только логи и кэш.

### D6. Время в dual boot
Windows по умолчанию держит аппаратные часы в локальном времени, Linux — в UTC. Переключаем Windows на UTC
(ключ реестра `RealTimeIsUniversal`, см. INSTALL.md), иначе часы будут прыгать на 3 часа.

### D7. Своп: zram + своп-файл 20 ГиБ, гибернация через suspend-then-hibernate
Ноутбук бывает закрыт по 2–3 дня, во сне он за это время посадит батарею, а открытое пропадёт. Поэтому:
- zram — быстрый своп в сжатой памяти, используется первым (выше приоритет);
- `/swap/swapfile` 20 ГиБ в отдельном subvolume `@swap` — для гибернации (в zram образ сохранить нельзя: он живёт в RAM);
- при закрытой крышке — сон, через 3 часа автоматически гибернация (`HibernateDelaySec=3h`);
- ядру передаются `resume=UUID=<Arch> resume_offset=<смещение файла>`, initramfs на systemd-хуках сам подхватывает образ.
Условие: Secure Boot выключен (с ним ядро в режиме lockdown запрещает гибернацию).
Отвергнуто: отдельный swap-раздел — лишний раздел, а размер своп-файла потом легко поменять.

### D8. Доступ к Claude — первым делом на каждом этапе
Claude доступен только через VPN (Throne / sing-box). До стирания диска сохраняем конфиги Throne и проверяем
`sing-box` в live-среде. Пока Arch без графики, VPN поднимается через `sing-box` из консоли, Claude на телефоне — запасной вариант.
Подробности в `APPS.md`.

### D9. Obsidian: одно хранилище на Share для обеих систем
Заметки нужны и в Windows, и в Arch, поэтому хранилище лежит на Share: `S:\obsidian\<хранилище>` в Windows = `/mnt/share/obsidian/<хранилище>` в Arch.
Обе системы открывают одни и те же файлы, синхронизация не нужна (одновременно работает только одна ОС).
- Это исключение из правила «на Share только не-текстовое»: код по-прежнему только в `~/projects` под git.
- Share не попадает в BTRFS-снапшоты, поэтому история и бэкап заметок — через git (плагин Obsidian Git) с пушем в Gitea.
  В репозитории хранилища: `git config core.autocrlf false` и `git config core.fileMode false` (NTFS не хранит права Linux).
- Имена файлов только допустимые в Windows (без `: * ? " < > |`); опция `windows_names` в fstab не даст создать другие из Linux.
- Плагины и настройки в `.obsidian` общие для обеих систем — ставятся один раз.
Отвергнуто: хранилище в `~/` на Arch — из Windows его не видно; Syncthing между двумя ОС на одном ноутбуке — лишняя сложность.

### D10. Раскладка Share и настройки программ под неё
Всё, с чем работают программы (кроме кода), лежит на Share. Это переживёт переустановку любой из систем и видно из обеих.
Корень Share — только эти папки, файлы в корень не класть:
```
Share (S:\ в Windows, /mnt/share в Arch)
├── 3d/
│   ├── blender/<проект>/     .blend + textures/ (пути относительные)
│   └── print/<модель>/       .stl / .3mf / .gcode для Creality Print
├── audio/
│   ├── ableton/<проект> Project/   проект Ableton целиком (Collect All and Save)
│   ├── fl-studio/<проект>/         .flp + экспорт сэмплов
│   ├── samples/                    общая библиотека сэмплов для обеих DAW
│   ├── presets/                    пресеты Guitar Rig и плагинов (копия, см. ниже)
│   └── renders/                    готовые миксы и стемы
├── obsidian/<хранилище>/     заметки (D9), история через git
├── docs/                     документы, PDF, Office-файлы
├── media/                    фото, видео, скриншоты
└── tmp/ГГГГ-ММ/              временное, чистить раз в квартал
```
Настройки программ:
- **Blender** (Arch): проекты в `3d/blender/`. Перед сохранением: File → External Data → Make Paths Relative,
  чтобы текстуры находились с любой системы. Preferences → Save & Load → Save Versions = 2 (страховка `.blend1`, `.blend2`).
- **Creality Print**: экспорт и gcode в `3d/print/`.
- **Ableton Live** (Windows): проекты сохранять в `S:\audio\ableton\`; перед закрытием проекта — File → Collect All and Save,
  тогда все сэмплы копируются в папку проекта и он не «ломается» при переносе.
- **FL Studio** (Windows): проекты в `S:\audio\fl-studio\`; Options → File settings → Browser extra search folders → добавить `S:\audio\samples`.
  Для архива проекта целиком — File → Export → Project data files (собирает `.flp` вместе с сэмплами).
- **Guitar Rig 7** (Windows): пресеты живут в Documents (User Content Native Instruments). Это место оставляем по умолчанию,
  но после изменений копируем пользовательские пресеты в `S:\audio\presets\guitar-rig\` — так они переживут переустановку Windows.
- Сами программы и плагины (VST) ставятся на C:, на Share только проекты и сэмплы.

Бэкап: Share не попадает в снапшоты BTRFS. Obsidian защищён git; для `3d/` и `audio/` нужен отдельный бэкап
(на домашний сервер через WireGuard или на внешний диск) — настроим после установки.
