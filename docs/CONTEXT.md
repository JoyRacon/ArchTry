# Контекст: переразметка Matebook и dual boot Windows + Arch (Hyprland)

Сводка из прошлых чатов с Claude.ai. Источники:
- «Автоматизированная установка Arch Linux с Hyprland на Huawei Matebook» (апрель 2026) — первоначальный план, роадмап, проектный скилл `arch-hyprland-setup`
- «Visual Match ML-модуль: архитектура и блокеры» (сентябрь 2026) — реальная диагностика диска и пересмотр разметки, backlog issue #17

> Где планы расходятся — актуален сентябрьский вариант (раздел 3). Апрельская схема (exFAT, 300/400/280) устарела.

## 1. Железо

- Huawei Matebook X Pro 2020, MACHC-WAE9LP
- CPU Intel i7-10510U (Comet Lake), 16 GB RAM
- GPU: Intel UHD 620 + NVIDIA MX250 (гибрид) → план: только Intel, NVIDIA гасить через `envycontrol -s integrated`
- WiFi Intel AX201 (iwlwifi), BT Intel 5.0
- Fingerprint Goodix — не поддерживается; звук — часть динамиков может не работать
- SSD: TOSHIBA KXG60ZNV1T02, 1 ТБ (≈954 ГиБ), GPT, UEFI

## 2. Текущее состояние диска (снято 2026-09, из Windows)

| # | Раздел | Размер | Примечание |
|---|---|---|---|
| 1 | EFI (System) | 100 МБ | мал для ядер Linux |
| 2 | MSR (Reserved) | 16 МБ | |
| 3 | C: NTFS | ~169 ГиБ | свободно ~19.5 ГБ — забит |
| 4 | Recovery | ~952 МБ | |
| 5 | D: NTFS | 100 ГиБ | свободно ~80 ГБ, рабочие каталоги, «удобная помойка» |
| — | Неразмечено | ~684 ГиБ (734 ГБ) | одним куском в хвосте диска |

## 3. Целевая разметка (последний вариант, сентябрь)

Решение: разметить **весь диск заново**, Windows переустановить.
Это было моё (Claude) предложение в конце обсуждения — финально не подтверждено, сверить перед стартом.

Порядок на диске слева направо:

| Раздел | Размер | ФС | Назначение |
|---|---|---|---|
| ESP | 1 ГиБ | FAT32 | один общий загрузчик для Windows и Linux |
| Windows | 250 ГиБ | NTFS | Ableton, FL Studio, Guitar Rig, LM Studio, Visual Studio, Creality, игры |
| Recovery | 1 ГиБ | NTFS | создаёт установщик Windows |
| Arch | 350 ГиБ | BTRFS | разработка, docker, VS Code, Blender, dotfiles |
| Share | 250 ГиБ | NTFS | media/, 3d/ (blend, stl), docs/, audio/ (проекты DAW) |
| Запас | ~100 ГиБ | — | не размечать; примыкает к Share для расширения |

Обоснования:
- ESP 1 ГиБ общий: при чистой разметке второй ESP не нужен; 100 МБ по умолчанию мало под ядра/initramfs.
- Share на NTFS, а не exFAT (пересмотр апрельского решения): журналируемая, Linux пишет через `ntfs3`.
- Запас оставлен намеренно: BTRFS и NTFS расширяются онлайн, недобрать сейчас не страшно.
- Если бы не переразмечать с нуля (промежуточный вариант): свой ESP 1 ГиБ + Arch BTRFS в хвосте, Windows-разделы не трогать, D: использовать как шару.

BTRFS subvolumes:
```
@          → /
@home      → /home
@var       → /var
@snapshots → /.snapshots
```
Опции монтирования: `compress=zstd,noatime`.

## 4. Порядок работ

1. Сохранить данные с C: и D: (бэкап).
2. В Windows: `manage-bde -status` → приостановить/отключить BitLocker; отключить Fast Startup (иначе NTFS остаётся «грязной» и Linux не пишет в Share).
3. BIOS/UEFI: проверить режим UEFI, Secure Boot — отключить на время установки.
4. Live-USB (Ventoy): проверить железо — WiFi, тачпад, звук, внешний монитор.
5. Разметить весь диск по схеме из раздела 3.
6. **Сначала** установить Windows в готовый раздел (установщик Windows перетирает загрузочные записи — поэтому до Arch).
7. Затем Arch: archinstall (или вручную pacstrap/genfstab/arch-chroot), BTRFS subvolumes, **systemd-boot**, NetworkManager.
8. Проверить dual boot в обе стороны; смонтировать Share через fstab (ntfs3).
9. Hyprland + waybar, wofi, mako, kitty; dotfiles в git, раскатка через GNU Stow.
10. Рабочее окружение: docker, ssh-конфиги, Claude Code CLI.
11. После стабилизации — агент трекинга активности (command-hub #59, использует `hyprctl`).

Проверки в live-среде: `ls /sys/firmware/efi` (UEFI), `iwctl station wlan0 connect SSID` (WiFi).

## 5. Правила раскладки файлов (чтобы не было свалки)

- Код — только на Arch в `~/projects`, только под git. Никогда на Share.
- Share — только не-текстовое, что открывают обе системы. Файлы в корень Share не класть, только в `media/`, `3d/`, `docs/`, `audio/`.
- Временное — `share/tmp/ГГГГ-ММ/`, чистить раз в квартал.
- Blender ставится на Arch, проекты .blend/.stl — на Share.

## 7. Инструкции для Claude Code

- Перед любыми деструктивными командами (fdisk, mkfs, wipefs, rm -rf) — предупреждать, объяснять и ждать подтверждения.
- Давать полные команды и полные файлы с путями, объяснять что и зачем.
- Перед рискованными изменениями на Arch — BTRFS-снапшот.
- Комментарии в конфигах: пользовательские — на русском, технические — на английском.
- Проблемы и решения записывать в `docs/TROUBLESHOOTING.md`, решения — в `docs/DECISIONS.md`.
